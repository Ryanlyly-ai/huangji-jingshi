# 卦序与方向约定

## 原文语义

传世《观物外篇》解释先天图时说：

- 数往者顺，是左旋；
- 知来者逆，是右行；
- 四正为乾、坤、坎、离。

这些词首先描述图义，不能未经说明就等同于屏幕上的顺时针、逆时针，也不能直接等同于程序数组的递增、递减。

## 默认核心的程序落地要求

未来加入年度配卦前，必须同时固定：

1. 所据图版与版本；
2. 图的上、下、左、右方位；
3. 卦象由内向外还是由外向内读取；
4. “左旋、右行”在该图上的视觉路径；
5. 数组索引 0 所代表的卦；
6. 索引递增方向；
7. 乾、坤、坎、离是排除整卦、排除部分爻，还是在不同层级采用不同规则。

默认核心 API 不输出值年卦。具名可选方案必须逐项固定上述选择，并携带证据等级。

## 已实现的具名方案

`ma-zeng-2020` 依据马振国、曾华才配表所绘先天圆图，将顺时针数组固定为：

```text
31, 30, ..., 1, 0, 32, 33, ..., 62, 63
```

其中数组索引递增就是该图版的视觉顺时针方向。排除乾 `63`、坤 `0`、坎 `18`、离 `45` 后得到六十值卦；一元内 2160 年值卦从复 `32` 起。这是对一个特定现代方案的精确定义，不反向声称所有先天图版都必须采用相同屏幕方向。

## 方案数据结构原则

```ts
interface HexagramSequenceDefinition {
  id: string;
  sourceId: string;
  diagramOrientation: string;
  startHexagram: string;
  indexDirection: "forward" | "reverse";
  semanticDirection: "数往" | "知来";
  exclusions: readonly string[];
  evidenceLevel: EvidenceLevel;
}
```

这样可以并存多个学术方案，而不把其中一种伪装成唯一原意。
